# Панель агентов e-com Viled

Сайт, где видно всю систему агентов: какие агенты есть и работают ли они, архив дайджестов,
журнал запусков, задачи команды из дайджестов и SQL-запросы, из которых дайджест собирается.

| Страница | Что на ней |
|---|---|
| Обзор | счётчики, «решить сегодня» из последнего дайджеста, карточки агентов, сам последний дайджест |
| Агенты | статус (работает / в работе / в плане), расписание, канал, ответственные, источники, последний запуск |
| Дайджесты | архив с фильтром по типу: день, неделя, месяц, квартал, полугодие, год, с начала года |
| Задачи | пункты «Решить / с кем поговорить» из всех дайджестов, по людям, с отметкой «готово» |
| Запуски | журнал запусков агентов (`runs.jsonl`), пока его нет — восстанавливается по сохранённым дайджестам |
| Запросы | SQL дайджеста по разделам из `SECTIONS` в `digest.py`, с базой Metabase и текстом запроса |

## Важно: данных в репозитории нет

Репозиторий публичный, поэтому в нём только код. Дайджесты, имена команды, SQL и токены лежат вне
репозитория и подставляются при сборке:

- `--digest-dir` — папка агента дайджестов (`out/`, `queries/`, `digest.py`, опционально `runs.jsonl`);
- `--config-dir` — настройки панели: `agents.json`, `team.json`, `tasks.json`. Формат — в `config.example/`.

Токены Telegram и Metabase панели не нужны совсем: она только читает файлы, которые агент уже сохранил.

## Запуск локально

```bash
python3 -m panel.build --digest-dir /mnt/project-files/ecom-digest \
                       --config-dir /mnt/project-files/agents-panel/config --out dist
python3 -m http.server -d dist 8000      # открыть http://localhost:8000
python3 -m unittest discover -s tests -t .
```

Нужен только Python 3.10+, внешних зависимостей нет.

## Хостинг: Cloudflare Pages + Cloudflare Access

Предлагаемый вариант. Бесплатно, вход по почте с одноразовым кодом (до 50 человек), сайт закрыт от
посторонних, данные не попадают в GitHub.

1. Зарегистрироваться на cloudflare.com, создать проект Pages с именем `viled-agents`
   (Workers & Pages → Create → Pages → Direct upload).
2. Zero Trust → Access → Applications → Add → Self-hosted, домен `viled-agents.pages.dev`,
   политика Allow: список почт команды (или домен `@viled.kz`).
3. Создать API-токен с правом «Cloudflare Pages: Edit» и добавить в переменные облачного окружения проекта
   `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`, а в Network access разрешить `api.cloudflare.com`.
4. Агент дайджестов после отправки в Telegram запускает `scripts/deploy.sh`, и сайт обновляется каждое утро.

Почему не GitHub Pages: сайт на нём всегда публичный, а в дайджестах выручка и внутренние задачи.

## Что дальше

- Агент дайджестов дописывает строку в `runs.jsonl` после каждого запуска:
  `{"ts": "2026-11-07T03:39:00+00:00", "agent": "digest", "status": "ok", "summary": "дневной за 06.11", "digests": ["digest_2026-11-06"]}`
  (`status`: ok / partial / error). Тогда на странице «Запуски» будут ошибки источников, а не только время.
- Общий статус задач для всей команды: сейчас галочка хранится в браузере, общий — в `tasks.json`.
  Следующий шаг — маленький backend (Cloudflare Worker + D1) или Telegram-кнопки «сделано» в боте.
- Вкладки для агента приоритетов и маркетплана с вкладкой трейд-менеджера.
